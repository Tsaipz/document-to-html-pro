# 文轉網 PRO V9.0｜按鈕修復 + Word 原稿排版優先

此版本可直接替換 V8 專案的全部靜態檔案。**不是已上線版本**：請把 ZIP 內的 `index.html`、`assets/`、`api/`、`README.md` 一併更新至 GitHub，再確認 Cloudflare 已完成部署。

## 修正

- 修正 V8 「開啟貼上排版」、「產生美化 HTML」、「查看排版預覽」等按鈕可能沒有反應的問題。原因是 `assets/paste.js` 引用了 `assets/app.js` 封閉作用域內的函式與狀態，現在改由明確的 `window.WZWCore` 接口呼叫。
- 貼上 Word 時保留安全的行內文字顏色、字級、段落對齊、粗斜體；不再把所有樣式刪除。新增「優先保留 Word 貼上的文字、顏色與段落樣式」開關。需要網站統一樣式時仍可使用 10 種模板。
- Word `.docx` 新增直接解析 OOXML 的原稿排版模式。保留可編輯的文字順序、常見標題、字色、大小、粗斜體、對齊、段落間距、清單、表格、內嵌圖片及基本寬度。圖片匯出採 `images/` 可讀路徑。
- 檔案轉換預設「保留原稿排版」。只有選擇「重新美化」才會自動套網站模板。
- 將 JSZip 3.10.1 固定為專案內本地依賴 `assets/vendor/jszip.min.js`（MIT 授權），避免 ZIP 讀取過度依賴外部 CDN。
- 仍保留 V7 批次佇列／暫停／取消、V8 原文貼上、Jodit 富文字編輯、CMS 檢查、圖片打包、SEO 與選配 AI API。

## 實際使用

1. 單份文件：左側選 Word／Excel／PPT／PDF，轉換模式選「保留原稿排版」再按「開始轉換」。確認右側即時預覽，可在進階編輯器微調。
2. 需要重新套用品牌樣式：轉換前切換「重新美化」，或轉換後按「重新套用樣式」。這會刻意取代原稿樣式。
3. 避免文字辨識錯誤：使用「貼上轉 HTML」直接貼 Word 或純文字；「載入範例內容」「清空貼上區」「產生美化 HTML」以及「查看排版預覽」都已重新接線。
4. 匯出有圖文件：使用「下載 HTML＋圖片 ZIP」，取得 `index.html` 和 `images/`。如果 HTML 要貼入網站 CMS，請先把圖片上傳到該網站圖庫、再替換路徑。
5. 批次轉換：一次加入多份文件，產出每份獨立 HTML 和圖片；套用的轉換模式對批次同樣有效。

## 必須了解的格式限制

| 格式 | 「保留原稿排版」能力 |
| --- | --- |
| DOCX | 可編輯的 HTML，保留常見行內樣式、表格、段落與圖片；不保證跟 Word 完全同一頁、同一分頁。浮動文字方塊、圖表、頁首頁尾、WordArt 等複雜物件可能遺失。 |
| XLSX／XLS | 保留工作表及儲存格/合併儲存格結構，複雜的 Excel 格式、條件格式、圖表及列印分頁不保證相同。 |
| PPTX | 依投影片擷取文字與相關圖片；**不保證**保留投影片物件座標、圖表、SmartArt、動畫或背景。若要真正的整頁視覺還原，需另外串接伺服器端 Office 轉圖／PDF 服務。 |
| PDF | 以逐頁圖片保留頁面外觀，但文字無法直接編輯；要變成可編輯文字時需選「重新美化」，擷取順序／OCR 辨識需人工校對。 |

**網頁用 HTML 和 Word／PPT 原生版面是不同排版模型，不可能在所有 CMS 同時保證逐像素相同、保留可編輯文字及對行內 CSS 相容。** 本版以 CMS 可上架和盡量保留來源樣式為主。

## 部署到 Cloudflare

1. 解壓縮此 ZIP，將 `index.html`、`assets/`、`api/`、`README.md` 更新至 `Tsaipz/document-to-html-pro` 的 GitHub 儲存庫根目錄；不要把整個資料夾再包一層。
2. Cloudflare 已連接 GitHub 自動部署時，提交後應有新 deployment；確認新版本顯示 `PRO 9.0`。
3. 若舊版還存在，嘗試強制重新整理（Mac `⌘ + Shift + R`）、檢查部署是否成功，以及 Cloudflare 快取。
4. **Cloudflare Workers 不能直接執行 PHP**；`api/ai.php` 是另行部署的選配代理服務，不會因靜態網站更新自動啟用。
5. DOMPurify／Mammoth／SheetJS／PDF.js／Jodit 等仍透過第三方 CDN 載入。若 CDN 被阻擋，相關功能無法運作；基礎 JSZip 已本地化。請確認網路、瀏覽器錯誤及 CSP。

## 測試與安全

- 已通過 Node.js 語法檢查；使用 Chromium + 測試用 sanitizer 替身做了瀏覽器互動驗證，包含按鈕、純文字、Word HTML 貼上、DOCX 字色字級對齊表格和圖片路徑。
- **實測並非等同完整上線驗收**：端到端測試仍須使用實際外部 DOMPurify CDN、正式 Cloudflare 網址，以及真實 CMS 後台保存結果驗收。
- 不要把任何秘密金鑰提交至 GitHub。最終 CMS 的伺服器仍應檢查及清理所有 HTML。
